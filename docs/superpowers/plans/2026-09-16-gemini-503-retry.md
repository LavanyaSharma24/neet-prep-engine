# Gemini 503 Retry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `ask_gemini()` retry transient `503 UNAVAILABLE` errors (up to 2 retries, 1s/2s backoff) while still failing immediately on `429` quota-exhaustion errors.

**Architecture:** `ask_gemini()` currently wraps `client.models.generate_content()` in a single try/except that converts any non-`GeminiError` exception straight into `GeminiError`. Change that to a small retry loop: on a `google.genai.errors.ServerError` whose `.code == 503`, sleep (1s, then 2s) and retry, up to 2 retries (3 attempts total); any other exception — including `ClientError` with `.code == 429` — still converts to `GeminiError` on the first failure, exactly as today. Both `ask_gemini` callers (`cross_check_answer`'s primary/secondary calls and `_ask_judge`, which also calls `ask_gemini`... actually `_ask_judge` calls `client.models.generate_content` directly, not `ask_gemini` — confirmed by reading gemini_client.py:112-120) get the retry for free since they share the same code path where applicable.

**Tech Stack:** Python, `google-genai` SDK (`google.genai.errors.ServerError` / `ClientError`), `pytest` + `monkeypatch` for tests (matching the existing style in `api/test_gemini_client.py`), `time.sleep` for backoff.

**Spec:** This conversation (no separate spec doc) — requirements given directly by the user:
- Retry only `503 UNAVAILABLE`, not `429` quota errors.
- Up to 2 retries with backoff `1s`, then `2s`.
- After retries exhausted, raise `GeminiError` as before.
- Applies to both primary and judge model calls that go through `ask_gemini()`.
- Add a test simulating 503-then-success (retry works).
- Add a test confirming 429 is NOT retried (fails immediately).

## Resolved decision (confirmed with user)

`_ask_judge()` does **not** call `ask_gemini()` today — it calls `client.models.generate_content()` directly (gemini_client.py:112-123) with its own system prompt (`_JUDGE_SYSTEM_PROMPT`), duplicating the same call/error-handling shape `ask_gemini()` uses with `SYSTEM_PROMPT`. To get retry behavior on the judge call too (per user's explicit choice), `ask_gemini()` gets a new optional `system_prompt: str = SYSTEM_PROMPT` parameter, and `_ask_judge()` is refactored to call `ask_gemini(prompt, model_name=SECONDARY_MODEL, system_prompt=_JUDGE_SYSTEM_PROMPT)` instead of duplicating the client call. `_ask_judge` keeps its existing fail-closed `except Exception: return False` around the call — this now also catches `GeminiError`/`GeminiRefusal` from `ask_gemini`, consistent with "judge failure fails closed." One behavior nuance: `ask_gemini()` raises `GeminiRefusal` if the response text exactly equals `REFUSAL_TEXT` ("I don't have a confident answer.") — this sentinel is defined for the NEET-answering prompt, not the judge's YES/NO prompt, so it's already vanishingly unlikely to collide with a real judge verdict, and `_ask_judge`'s blanket `except Exception` catches `GeminiRefusal` too and returns `False` (fail closed) exactly as it would for any other error, so this is not a correctness gap.

## Global Constraints

- Retry count: exactly 2 retries (3 total attempts) — copied verbatim from user's request.
- Backoff schedule: 1s then 2s — copied verbatim from user's request.
- Only `503` retries; `429` and everything else fails on first attempt.
- No new dependencies — `time.sleep` and `google.genai.errors` are already available (errors module ships with the already-installed `google-genai` SDK).
- Tests must stay offline/deterministic (no real network calls, no real `time.sleep` delays) — matching the existing `test_gemini_client.py` style (monkeypatch `_client`, no `genai.Client` construction).

```python
def _server_error(code: int) -> errors.ServerError:
    """Builds a real ServerError without needing a fake HTTP response —
    APIError.__init__ normally parses one, so we bypass __init__ and set
    just the .code attribute ask_gemini's retry check reads."""
    exc = errors.ServerError.__new__(errors.ServerError)
    exc.code = code
    return exc


def _client_error(code: int) -> errors.ClientError:
    exc = errors.ClientError.__new__(errors.ClientError)
    exc.code = code
    return exc
```

- [ ] **Step 3: Add the retry loop to `ask_gemini()`**

In `api/gemini_client.py`, add `import time` and `from google.genai import errors` near the top (after the existing `from google.genai import types` line), then replace the body of `ask_gemini()`:

```python
import time
...
from google.genai import errors

MAX_503_RETRIES = 2
RETRY_BACKOFF_SECONDS = (1, 2)


def ask_gemini(
    question: str, model_name: str = PRIMARY_MODEL, system_prompt: str = SYSTEM_PROMPT
) -> str:
    attempt = 0
    while True:
        try:
            client = _client()
            response = client.models.generate_content(
                model=model_name,
                contents=question,
                config=types.GenerateContentConfig(system_instruction=system_prompt),
            )
            break
        except GeminiError:
            raise
        except errors.ServerError as exc:
            if exc.code == 503 and attempt < MAX_503_RETRIES:
                time.sleep(RETRY_BACKOFF_SECONDS[attempt])
                attempt += 1
                continue
            raise GeminiError(f"Gemini request failed ({model_name}): {exc}") from exc
        except Exception as exc:  # network/SDK errors — surface as a clean 502 upstream
            raise GeminiError(f"Gemini request failed ({model_name}): {exc}") from exc

    text = (response.text or "").strip()
    if not text:
        raise GeminiError(f"Gemini returned an empty response ({model_name})")
    if text == REFUSAL_TEXT:
        raise GeminiRefusal(text)
    return text
```

Note: `429` errors are `ClientError`, not `ServerError`, so they fall through to the generic `except Exception` branch and convert to `GeminiError` immediately — no retry — matching the requirement without needing an explicit 429 check. The new `system_prompt` param defaults to `SYSTEM_PROMPT`, so `cross_check_answer()`'s existing calls (`ask_gemini(question, PRIMARY_MODEL)` / `ask_gemini(question, SECONDARY_MODEL)`) are unaffected.

```python
def _ask_judge(question: str, answer_a: str, answer_b: str) -> bool:
    """Asks the (cheaper) secondary model whether two candidate answers
    substantively agree. A judge failure fails closed — treated as
    disagreement, never as a silent agreement — since serving an unverified
    answer is the one outcome the architecture doc rules out entirely."""
    prompt = (
        f"Question: {question.strip()}\n\n"
        f"Answer A: {answer_a.strip()}\n\n"
        f"Answer B: {answer_b.strip()}\n\n"
        "Do these substantively agree?"
    )
    try:
        verdict = ask_gemini(
            prompt, model_name=SECONDARY_MODEL, system_prompt=_JUDGE_SYSTEM_PROMPT
        )
    except Exception:
        return False

    return verdict.strip().upper() == "YES"
```

This preserves the judge's actual prompt (`_JUDGE_SYSTEM_PROMPT`, the yes/no comparison instruction) via the new `system_prompt` param, while gaining `ask_gemini`'s 503 retry. The existing `except Exception: return False` still fails closed on any error, including a `GeminiRefusal` raised if the judge's own YES/NO answer happened to exactly equal `REFUSAL_TEXT` (practically impossible, and even so, still correctly treated as "not agreed").
